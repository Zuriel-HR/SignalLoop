# Sesión: diseño inicial del intérprete versionado

## 1. Propósito

Registrar el análisis de `SignalLoopMixto`, la Central Quarkus y el plan de integración/versionado V0–V2.

## 2. Antecedentes

Central actualmente persiste y sirve logs ordenados. SignalLoopMixto tiene un motor de referencia Python y ciclo de aprendizaje. El responsable confirmó que es solo referencia; Central es el codebase destino único.

## 3. Problema

No existe aún un intérprete real conectado a la Central ni snapshots ejecutables autocontenidos V0/V1/V2.

## 4. Alcance

Se revisaron código y documentación existentes, se preparó SPEC-0003, se señaló su estado en README/CONTEXT y se ejecutó validación no destructiva del motor de referencia.

## 5. No objetivos

No se portó el motor a Java, no se crearon snapshots de runtime y no se cambió el SQL ni la API.

## 6. Propuesta / diseño

- Mantener Python como oráculo independiente al portar la semántica a una interfaz de intérprete Java.
- Mantener la implementación en `central/`; usar SignalLoopMixto solo como referencia/oráculo temporal de paridad.
- Proponer baseline y carpetas de exportación V0/V1/V2 bajo `central/`; PostgreSQL Central guarda generaciones runtime y versión activa.
- Mantener candidata, activas e historial de corridas separados; outcomes solo para el evaluador.

## 7. Validación ejecutada

- `python -m pytest tests`: no ejecutable porque no está instalado `pytest`; no se instalaron dependencias.
- `python -m compileall -q aprendiz`: pasó.
- Ejecución directa del motor con reglas base: V0 coincide en C3 y C6 (2/6); R1/R2 se mantuvieron fuera de esa cuenta.
- No se ejecutó `central/mvnw.cmd test`: su perfil puede limpiar la base `signalloop_test`, cuya seguridad/descarte no se verificó.
- Verificación documental: SPEC-0003 cumple metadatos y apartados AKB; se corrigió la referencia al schema de caso.

## 8. Riesgos

- Divergencia entre semánticas Python/Java.
- Desalineación entre casos del banco y logs/escenarios persistidos.
- Fuga de outcomes o alteración del conjunto reservado/test.

## 9. Preguntas abiertas

- Confirmar lenguaje productivo, payload, estructura canónica snapshots y campos que definen `pasa`.
- Definir compuerta/aprobación y cuándo migrar JSONL a PostgreSQL.

## 10. Próximo paso

Revisar/aceptar SPEC-0003; después implementar V0 e intérprete Java detrás de interfaz y correr comparación por C1–C6 más casos reservados.
